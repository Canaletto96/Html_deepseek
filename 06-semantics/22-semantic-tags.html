Урок 22. Семантические теги

1. Проблема «дивового супа»

До HTML5 разработчики строили всё через <div> с классами: 

<div class="header">...</div>
<div class="nav">...</div>
<div class="main">...</div>
<div class="sidebar">...</div>
<div class="footer">...</div>

Это называется «дивовый суп» (div soup). Проблемы:

  • Браузер не понимает смысл — все блоки для него одинаковые.
  • Screen reader не может навигировать — не знает, где шапка, где меню.
  • Поисковики не видят структуру — не понимают, что главное на странице.
  • Код сложно читать — 50 одинаковых <div>.

В HTML5 появились семантические теги — они выглядят как обычные блоки, но говорят браузеру, что это за блок.

2. Обзор семантических тегов

Тег Что означает Где использовать
<header> Шапка Логотип, заголовок, навигация вверху страницы или раздела
<nav> Навигация Главное меню, хлебные крошки, пагинация
<main> Основное содержимое Уникальный контент страницы (один на страницу)
<section> Раздел Смысловой раздел с заголовком
<article> Статья Самодостаточный контент: пост, новость, карточка товара
<aside> Сбоку Боковая панель: реклама, ссылки, дополнительная информация
<footer> Подвал Копирайт, контакты, ссылки внизу страницы или раздела

3. Визуальная схема страницы

Типичная структура сайта:
<header>
<nav>
<main>
<aside>
<footer>

4. Тег <header> — шапка

Верхняя часть страницы или раздела. Обычно содержит логотип, название, навигацию, контактную информацию. 

<header>
    <img src="logo.png" alt="Логотип" width="100">
    <h1>Мой блог</h1>
    <nav>
        <a href="/">Главная</a>
        <a href="/about">О нас</a>
    </nav>
</header>
Важно: <header> может быть не только у страницы, но и у отдельного <article> или <section>. Например, шапка статьи с заголовком и датой. 
<article>
    <header>
        <h2>Как варить кофе</h2>
        <p>Опубликовано: 15 января 2026</p>
    </header>
    <p>Текст статьи...</p>
</article>
Не путай с <head>! Это разные теги:
  • <head> — служебная информация документа (meta, title).
  • <header> — видимая шапка страницы.

5. Тег <nav> — навигация

Блок с основными ссылками для перемещения по сайту. Не каждая группа ссылок — <nav>. 

<nav>
    <ul>
        <li><a href="/">Главная</a></li>
        <li><a href="/blog">Блог</a></li>
        <li><a href="/contact">Контакты</a></li>
    </ul>
</nav>

Когда использовать <nav>:

  • Главное меню сайта
  • Хлебные крошки («Главная → Блог → Статья»)
  • Пагинация (страницы 1, 2, 3...)
  • Оглавление статьи
Не используй <nav> для групп ссылок в тексте (например, «полезные ссылки» в подвале). <nav> — только для основной навигации.

Screen reader читает <nav> как «навигация» и позволяет пропустить её или перейти к ней — это удобно для незрячих.

6. Тег <main> — основное содержимое

Главный контент страницы. То, ради чего пользователь пришёл. Один на страницу. 

<main>
    <h1>Добро пожаловать</h1>
    <p>Это основной контент страницы.</p>
</main>

Что НЕ должно быть внутри <main>:

  • Шапка (<header>)
  • Навигация (<nav>)
  • Подвал (<footer>)
  • Боковые панели (<aside>)
Зачем один: screen reader читает <main> как «основное содержимое» и позволяет перейти к нему одним нажатием, пропустив шапку и меню. Если <main> несколько — это сбивает.

7. Тег <section> — раздел

Смысловой раздел страницы. Обычно содержит заголовок и связанный с ним контент. 

<section>
    <h2>Услуги</h2>
    <p>Мы предлагаем разработку сайтов, дизайн и консультации.</p>
</section>
Не каждую «коробку» делать <section>. Если блок нужен просто для группировки (без смыслового заголовка) — используй <div>. <section> — только для смысловых разделов.

Правило: у каждого <section> должен быть заголовок (<h2>–<h6>). Если заголовка нет — скорее всего, это не <section>, а <div>.

8. Тег <article> — статья

Самодостаточный контент, который можно «вырезать» и опубликовать в другом месте без потери смысла.

Что может быть статьёй:

  • Пост в блоге
  • Новость
  • Карточка товара
  • Комментарий пользователя
  • Пост в соцсети
<article>
    <header>
        <h2>Как выбрать ноутбук</h2>
        <p><time datetime="2026-01-15">15 января 2026</time></p>
    </header>
    <p>При выборе ноутбука обратите внимание на...</p>
    <footer>
        <p>Автор: Иван Иванов</p>
    </footer>
</article>

<article> vs <section>

<section> <article>
Смысл Раздел внутри чего-то Самодостаточная единица
Можно вырезать Нет (потеряет контекст) Да (останется смысл)
Пример Раздел «Услуги» на главной Пост в блоге, карточка товара

9. Тег <aside> — сбоку

Контент, косвенно связанный с основным: реклама, ссылки на другие статьи, боковая панель, «читайте также». 

<aside>
    <h3>Читайте также</h3>
    <ul>
        <li><a href="/post-1">Как варить кофе</a></li>
        <li><a href="/post-2">10 рецептов чая</a></li>
    </ul>
</aside>

Screen reader может пропустить <aside>, если пользователь хочет только основной контент.

10. Тег <footer> — подвал

Нижняя часть страницы или раздела. Копирайт, контакты, ссылки, кнопка «наверх». 

<footer>
    <p>&copy; 2026 Мой блог. Все права защищены.</p>
    <p>Контакты: <a href="mailto:info@example.com">info@example.com</a></p>
</footer>

Как и <header>, <footer> может быть не только у страницы, но и у статьи (с информацией об авторе).

11. Полная структура страницы

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Мой блог</title>
</head>
<body>

    <header>
        <h1>Мой блог</h1>
        <nav>
            <a href="/">Главная</a>
            <a href="/blog">Блог</a>
            <a href="/about">О нас</a>
        </nav>
    </header>

    <main>
        <h2>Последние статьи</h2>

        <article>
            <header>
                <h3>Как варить кофе</h3>
                <p><time datetime="2026-01-15">15 января 2026</time></p>
            </header>
            <p>Текст статьи...</p>
            <footer>Автор: Иван</footer>
        </article>

        <article>
            <header>
                <h3>10 рецептов чая</h3>
                <p><time datetime="2026-01-10">10 января 2026</time></p>
            </header>
            <p>Текст статьи...</p>
        </article>
    </main>

    <aside>
        <h3>Популярное</h3>
        <ul>
            <li><a href="#">Лучшие сорта чая</a></li>
            <li><a href="#">Кофе для начинающих</a></li>
        </ul>
    </aside>

    <footer>
        <p>&copy; 2026 Мой блог</p>
    </footer>

</body>
</html>

12. Дерево структуры

<body>
├── <header>         ← шапка
│   ├── <h1>        ← заголовок страницы
│   └── <nav>       ← навигация
│
├── <main>           ← основной контент
│   ├── <article>    ← первая статья
│   │   ├── <header> ← шапка статьи
│   │   └── <footer> ← подвал статьи
│   │
│   └── <article>    ← вторая статья
│
├── <aside>          ← боковая панель
│
└── <footer>         ← подвал страницы

13. Как браузер и поисковики это видят

Для screen reader

Пользователь нажимает клавишу и перескакивает между регионами:

  • <nav> → «навигация, пропустить или перейти»
  • <main> → «основное содержимое»
  • <aside> → «дополнительно»
  • <footer> → «подвал»

Для поисковиков (Google, Яндекс)

Алгоритмы понимают структуру: что в <main> — важнее, что в <article> — это отдельная тематическая единица, что в <aside> — второстепенно.

Семантика ≠ SEO-магия. Сами по себе теги не поднимут сайт в выдаче. Но они помогают поисковикам понять, что где. А это косвенно влияет на позиции.

14. Частые ошибки

Ошибка Почему плохо
Несколько <main> на странице Разрешён только один
Шапка внутри <main> Шапка — вне main
Использовать <section> без заголовка Семантика теряется, лучше <div>
Использовать <article> для всего Это самодостаточный контент, а не любая коробка
Каждую группу ссылок делать <nav> <nav> — только для основной навигации
Путать <header> и <head> Совершенно разные теги
Заменять все <div> на <section> Теряется смысл — <section> не универсальная замена

15. Когда семантика НЕ нужна

Если блок — чисто декоративный (обёртка для сетки, контейнер для стилей), используй <div>. Он не несёт смысла. 

<!-- Просто обёртка для CSS-grid -->
<div class="grid-container">
    <div class="grid-item">...</div>
    <div class="grid-item">...</div>
</div>

<div> — это нормально. Его не надо бояться. Просто для смысловых блоков используй семантические теги.

16. Практическое задание

Задание 1. «Структура блога»

Создай файл 22-practice.html. Собери страницу блога:

  • <header> с названием блога и <nav> (Главная, Блог, О нас).
  • <main> с 2–3 <article>. У каждой статьи — <header> с заголовком и датой.
  • <aside> с блоком «Популярные статьи» (список из 3–5 ссылок).
  • <footer> с копирайтом.

Задание 2. «Семантическая проверка»

  • Открой DevTools (F12) → Elements.
  • Найди <main>, <header> и т.д. — увидишь их в DOM.
  • Проверь через validator.w3.org — нет ли ошибок.

Задание 3. «Screen reader»

  • Установи NVDA (Windows) или используй VoiceOver (Mac) / TalkBack (Android).
  • Открой свою страницу.
  • Попробуй навигировать по регионам (в NVDA — клавиша D для landmark'ов).
  • Ты услышишь «навигация», «основное содержимое», «дополнительно» — это семантика в действии.

Задание 4. «Сравни div и section»

  • Сделай страницу с 5 <div class="section">.
  • Потом переделай на 5 <section> с заголовками.
  • Проверь через screen reader — разница слышна.

Задание 5. «Сломай и почини»

  • Сделай два <main> — проверь валидатором, увидишь ошибку.
  • Положи <header> внутрь <main> — увидишь предупреждение.
  • Сделай <section> без заголовка — это не ошибка, но семантика слабее. Подумай, зачем он там.

17. Что запомнить из урока

  • Семь семантических тегов: header, nav, main, section, article, aside, footer.
  • <header> — шапка страницы или раздела.
  • <nav> — основная навигация (меню, хлебные крошки).
  • <main> — главный контент, один на страницу.
  • <section> — смысловой раздел с заголовком.
  • <article> — самодостаточная единица (пост, новость, карточка).
  • <aside> — дополнительный контент (боковая панель).
  • <footer> — подвал страницы или раздела.
  • Семантика помогает: screen reader'ам, поисковикам и тебе самому (код читается легче).
  • Не всё — семантика. Для чисто декоративных обёрток — <div>.
  • Не путай <header> с <head>.
  • Не путай <section> с <article>: section — часть, article — целое.
