Урок 21. Fieldset, legend, datalist, output

1. Зачем нужна группировка

Когда в форме много полей, их нужно разбивать на смысловые группы: «Личные данные», «Контакты», «Оплата». Это помогает и визуально, и для screen reader'ов.

Для этого есть два тега:

Тег Что делает
<fieldset> Группа полей с рамкой
<legend> Заголовок группы (встроен в рамку)

2. Тег <fieldset>

<fieldset> — контейнер для группы связанных полей. По умолчанию браузер рисует вокруг него рамку. 

<fieldset>
    <legend>Личные данные</legend>

    <label for="name">Имя:</label>
    <input type="text" id="name" name="name">

    <label for="email">Email:</label>
    <input type="email" id="email" name="email">
</fieldset>
Результат:
Личные данные

3. Тег <legend>

<legend> — заголовок группы. Идёт первым внутри <fieldset>. Браузер «встраивает» его в верхнюю линию рамки. 

<fieldset>
    <legend>Способ доставки</legend>
    <!-- поля -->
</fieldset>

Особенности legend

  • Только один legend на fieldset.
  • Всегда идёт первым элементом.
  • Может содержать inline-теги (<strong>, <em>).

4. Зачем это нужно для доступности

Screen reader читает <legend> при входе в группу. Пользователь слышит: «Личные данные — группа полей» и понимает контекст.

Особенно важно для radio-групп. Без <fieldset> screen reader не понимает, что несколько radio связаны вопросом.

Пример: «Выберите способ доставки: [радио] Самовывоз [радио] Курьер [радио] Почта» — screen reader прочитает каждый радио как отдельное поле. С <fieldset> и <legend> он скажет «Способ доставки» перед группой, и всё встанет на место.

5. Атрибут disabled у fieldset

Можно отключить всю группу сразу — все поля внутри станут недоступны. 

<fieldset disabled>
    <legend>Раздел временно недоступен</legend>
    <input type="text" name="field1">
    <input type="text" name="field2">
</fieldset>
Результат (все поля отключены):
Раздел временно недоступен

6. Атрибут form у fieldset (необычный случай)

<fieldset> может иметь атрибут form — id формы, к которой он относится. Это полезно, если fieldset лежит вне формы, но должен отправляться с ней. 

<form id="myForm">
    <!-- поля -->
</form>

<fieldset form="myForm">
    <legend>Внешняя группа</legend>
    <input name="extra">   <!-- тоже отправится с myForm -->
</fieldset>
Редкий случай. Обычно fieldset лежит внутри form. Атрибут form нужен, если по вёрстке группа полей находится далеко от формы.

7. Тег <datalist> — список подсказок

<datalist> даёт автодополнение для текстового поля. Пользователь может выбрать из списка или ввести своё значение. 

<label for="browser">Браузер:</label>
<input list="browsers" id="browser" name="browser">

<datalist id="browsers">
    <option value="Chrome">
    <option value="Firefox">
    <option value="Safari">
    <option value="Edge">
    <option value="Opera">
</datalist>
Результат (начни вводить — появятся подсказки):

Как это работает

  • У <input> атрибут list ссылается на id datalist.
  • В datalist — набор <option> с атрибутом value.
  • Браузер показывает подсказки при вводе.
Важно: <datalist> — не выпадающий список, как <select>. Пользователь может ввести своё значение, которого нет в списке. Если нужно ограничить выбор — используй <select>.

datalist vs select

<datalist> <select>
Можно ввести своё Да Нет
Вид Поле ввода с подсказками Выпадающий список
Проверка на сервере Нужна своя Только из списка
Когда использовать Автодополнение, «свободный» выбор Строгий выбор из вариантов

Дополнительные подсказки в option

Можно показать и подпись, и значение:

<input list="fruits" name="fruit">
<datalist id="fruits">
    <option value="apple">Яблоко</option>
    <option value="banana">Банан</option>
    <option value="orange">Апельсин</option>
</datalist>

При выборе в поле попадёт value (латиницей), а в подсказке пользователь увидит текст («Яблоко»). Это удобно, когда на сервер нужно отправлять код, а не название.

8. Тег <output> — вывод результата

<output> — контейнер для результата вычислений. Обычно обновляется через JavaScript, но может работать и через простой атрибут oninput у формы. 

<form oninput="result.value = parseInt(a.value) + parseInt(b.value)">
    <input type="number" id="a" value="0"> +
    <input type="number" id="b" value="0"> =
    <output name="result" for="a b">0</output>
</form>
Результат (введи числа):
+ = 0

Атрибуты <output>

Атрибут Описание
name Имя для доступа из JavaScript и отправки на сервер
for Через пробел — id полей, значения которых участвуют в расчёте
form id формы, если output вне формы

Атрибут for важен для доступности: screen reader понимает, что этот output зависит от полей a и b.

Более сложный пример: сумма из range

<form oninput="total.value = parseInt(price.value) * parseInt(qty.value)">
    <label>Цена: <input type="number" id="price" value="100"></label>
    <label>Количество: <input type="number" id="qty" value="1"></label>
    <p>Итого: <output name="total" for="price qty">100</output> ₽</p>
</form>
Результат:

Итого: 100 ₽

Про JavaScript: oninput — это атрибут-обработчик события. Мы его коснулись, но JavaScript — отдельная тема. Здесь важно понять, что <output> — это контейнер для результата, а не «магический» тег.

9. Полная форма со всеми тегами

<form action="/order" method="post">

    <fieldset>
        <legend>Контактные данные</legend>

        <label for="name">Имя:</label>
        <input type="text" id="name" name="name" required>

        <label for="email">Email:</label>
        <input type="email" id="email" name="email" required>
    </fieldset>

    <fieldset>
        <legend>Доставка</legend>

        <label for="city">Город:</label>
        <input list="cities" id="city" name="city">
        <datalist id="cities">
            <option value="Москва">
            <option value="Санкт-Петербург">
            <option value="Казань">
        </datalist>

        <label for="address">Адрес:</label>
        <textarea id="address" name="address" rows="3"></textarea>
    </fieldset>

    <fieldset>
        <legend>Оплата</legend>

        <label class="inline">
            <input type="radio" name="payment" value="card" checked> Карта
        </label>
        <label class="inline">
            <input type="radio" name="payment" value="cash"> Наличные
        </label>
    </fieldset>

    <button type="submit">Оформить</button>
</form>

10. Стилизация fieldset и legend

Браузерное оформление fieldset устарело. Современный подход:

fieldset {
    border: 2px solid #ddd;
    border-radius: 8px;
    padding: 16px 20px;
    margin: 16px 0;
}

legend {
    padding: 0 10px;
    font-weight: bold;
    color: #b5651d;
}
Что можно стилизовать:
  • Рамку: border, border-radius
  • Отступы: padding, margin
  • Фон: background
  • Цвет и шрифт legend
Что сложно: точное позиционирование legend — браузер сам «врезает» его в рамку. Полностью переделать поведение сложно.

11. Частые ошибки

Ошибка Почему плохо
Несколько <legend> в одном fieldset Валиден только один
<legend> не первым элементом Должен идти сразу после открывающего fieldset
Использовать fieldset для вёрстки Это тег для группировки полей, не универсальный контейнер
datalist без id Поле не сможет его найти
Использовать datalist вместо select Пользователь сможет ввести своё значение
output без for Плохо для доступности — неясно, от чего зависит результат
Забыть name у output Значение не уйдёт на сервер

12. Практическое задание

Задание 1. «Форма заказа»

Создай файл 21-practice.html. Форма заказа с двумя fieldset:

  • «Контакты»: имя, email, телефон.
  • «Доставка»: город (через datalist), адрес (textarea).
  • Кнопка submit.

Задание 2. «Radio + fieldset»

  • Fieldset с legend «Способ доставки».
  • Три radio: Самовывоз, Курьер, Почта.
  • Проверь: без fieldset/legend смысл группы теряется, с ними — ясно.

Задание 3. «Datalist подсказки»

  • Поле «Любимый язык программирования».
  • Datalist с вариантами: JavaScript, Python, Java, C++, C#, Rust, Go, PHP.
  • Проверь: можно выбрать из списка или ввести своё.

Задание 4. «Калькулятор»

  • Форма с тремя input type="number": цена, количество, скидка (%).
  • Output с итоговой суммой: цена × количество × (1 − скидка/100).
  • Используй oninput в форме и атрибут for в output.

Задание 5. «Disabled-группа»

  • Сделай fieldset с disabled.
  • Внутри — 2–3 поля.
  • Проверь: они серые, нельзя изменить, не отправятся на сервер.

Задание 6. «Стилизация»

  • Стилизуй fieldset: рамка 2px, радиус 8px, padding 20px.
  • Legend: цвет #b5651d, жирный, padding 0 10px.
  • Проверь, как это выглядит с несколькими группами.

Задание 7. «Сломай и почини»

  • Добавь два legend в один fieldset — проверь валидатором.
  • Убери id у datalist — увидишь, что подсказки не работают.
  • Помести <legend> после полей — увидишь, что браузер сам его «перекинет» наверх.

13. Что запомнить из урока

  • <fieldset> — группа полей с рамкой.
  • <legend> — заголовок группы, идёт первым внутри fieldset. Только один.
  • Группировка важна для доступности — screen reader понимает контекст.
  • Особенно важна для radio-групп — иначе непонятно, к чему они относятся.
  • <fieldset disabled> — отключить всю группу сразу.
  • <datalist> — подсказки для input с возможностью ввести своё.
  • <input list="id"> связывается с <datalist id="id">.
  • <output> — вывод результата, обычно вычисляется через JavaScript.
  • У output важны атрибуты name (для отправки) и for (для доступности).
  • fieldset и legend стилизуются через CSS: рамка, отступы, цвет.
