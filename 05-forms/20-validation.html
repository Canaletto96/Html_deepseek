Урок 20. Валидация форм

1. Что такое валидация

Валидация — это проверка данных на корректность. Например:

  • Email должен содержать @ и домен.
  • Возраст — число от 1 до 120.
  • Пароль — минимум 8 символов.
  • Обязательные поля — не пустые.

Валидация бывает двух уровней:

Уровень Где происходит Зачем
Клиентская В браузере, до отправки Быстрая обратная связь для пользователя
Серверная На сервере, после отправки Безопасность, защита от подделки
Клиентская валидация НЕ ЗАМЕНЯЕТ серверную! Пользователь может отключить её в DevTools или отправить запрос через curl. На сервере всегда проверяй данные заново.

В этом уроке — клиентская валидация через HTML-атрибуты. Браузер делает её сам, без JavaScript.

2. Обзор атрибутов валидации

Атрибут Для чего Пример
required Поле обязательно <input required>
minlength / maxlength Длина текста minlength="8"
min / max Диапазон числа / даты min="18" max="120"
step Шаг изменения step="0.01"
pattern Регулярное выражение pattern="[0-9]{5}"
type Проверка формата type="email"
placeholder Подсказка (не валидация) placeholder="Введите email"

3. Атрибут required

Делает поле обязательным. Без него браузер не даст отправить форму. 

<label for="email">Email:</label>
<input type="email" id="email" name="email" required>
Результат (попробуй отправить пустым):

Браузер покажет подсказку: «Заполните это поле» или на английском — в зависимости от языка браузера.

required работает с: text, email, url, tel, password, number, checkbox, radio, file, select, textarea. Не работает с range и color (у них всегда есть значение).

4. Атрибуты minlength и maxlength

Ограничивают длину текста в символах.

<input type="text" name="name" minlength="2" maxlength="50">
<textarea name="comment" minlength="10" maxlength="500"></textarea>
Результат (имя от 2 до 20 символов):

Если ввести 1 символ — браузер скажет «Слишком короткое значение». Если больше 20 — не даст ввести лишнее.

5. Атрибуты min, max, step

Для type="number", range, date, time и др.

<!-- Возраст от 18 до 120 -->
<input type="number" name="age" min="18" max="120">

<!-- Цена с шагом 0.01 -->
<input type="number" name="price" min="0" step="0.01">

<!-- Дата не раньше 1 января 2020 -->
<input type="date" name="start" min="2020-01-01">

6. Атрибут pattern

Регулярное выражение для проверки формата. Очень мощный инструмент. 

<!-- Почтовый индекс: ровно 6 цифр -->
<input type="text" name="zip" pattern="[0-9]{6}">

<!-- Телефон в формате +7 (999) 999-99-99 -->
<input type="tel" name="phone" pattern="\+7\s?\(\d{3}\)\s?\d{3}-\d{2}-\d{2}">

<!-- Только латинские буквы и цифры -->
<input type="text" name="username" pattern="[A-Za-z0-9]+">
Результат (почтовый индекс — 6 цифр):
Правила pattern:
  • Регулярное выражение автоматически заключается в ^...$ — то есть должно совпасть целиком.
  • Не используй слэши /.../ — только саму regex.
  • Для сложных форматов добавь title — браузер покажет его в подсказке об ошибке.

Шпаргалка по regex для pattern

Что нужно Pattern
Только цифры [0-9]+
Ровно N цифр [0-9]{N}
От N до M цифр [0-9]{N,M}
Буквы и цифры [A-Za-z0-9]+
Русские буквы [А-Яа-яЁё]+
Email (простой) [^@]+@[^@]+\.[^@]+
Пароль 8+ символов .{8,}
Телефон РФ \+7\d{10}

8. Визуализация валидности через CSS

CSS-псевдоклассы :valid и :invalid позволяют стилизовать поля в зависимости от их валидности: 

input:valid {
    border-color: green;
}

input:invalid {
    border-color: red;
}

/* Только после того, как пользователь что-то ввёл */
input:invalid:not(:placeholder-shown) {
    border-color: red;
}
Результат (начни вводить — рамка меняет цвет):
Трюк с :not(:placeholder-shown): без него поле подсвечивается красным сразу, пока пользователь ничего не ввёл. С ним — только когда есть текст, и он невалиден.

9. Отключение валидации: novalidate

Иногда нужно отключить встроенную валидацию (например, для своей через JavaScript):

<form action="/submit" novalidate>
    <input type="email" required>
    <!-- браузер не будет проверять -->
</form>

Или отключить у конкретной кнопки через formnovalidate:

<button type="submit" formnovalidate>Отправить без проверки</button>

11. Что покажет браузер при ошибке

Текст сообщения зависит от языка браузера. Примеры на русском:

Проблема Сообщение
Пустое required-поле «Заполните это поле»
Некорректный email «Введите адрес электронной почты»
Короткий текст «Слишком короткое значение (минимум N символов)»
Число вне диапазона «Значение должно быть больше или равно N»
Не подходит под pattern «Проверьте это поле» + title, если есть
Изменить стандартный текст без JavaScript нельзя. Только через title можно добавить подсказку к pattern. Для кастомных сообщений нужен JavaScript (тема отдельного курса).

12. Частые ошибки

Ошибка Почему плохо
Полагаться только на клиентскую валидацию Можно обойти через DevTools, сервер должен проверять сам
Pattern со слэшами /.../ Не работает — только сама regex
Pattern без title Пользователь не понимает, что не так
Использовать required для color/range Не работает: у них всегда есть значение
Подсвечивать красным сразу при загрузке Раздражает — используй :not(:placeholder-shown)
type="text" вместо email/url Теряется бесплатная валидация
minlength у type="number" Не работает — используй min/max

13. Что валидация НЕ делает

  • Не проверяет, существует ли email — только формат.
  • Не проверяет уникальность — это работа сервера.
  • Не защищает от XSS — это работа сервера.
  • Не гарантирует корректные данные — можно обойти.
  • Не заменяет серверную валидацию — только дополняет её.
Золотое правило: клиентская валидация — для удобства пользователя. Серверная валидация — для безопасности. Нужны обе.

14. Практическое задание

Задание 1. «Форма регистрации»

Создай файл 20-practice.html. Форма с полями:

  • Имя — required, minlength="2", maxlength="30".
  • Email — type="email", required.
  • Телефон — type="tel", pattern="\+7\d{10}", title.
  • Возраст — type="number", min="18", max="120".
  • Пароль — type="password", minlength="8", required.
  • Кнопка submit.

Проверь все ошибки: пустые поля, плохой email, короткий пароль и т.д.

Задание 2. «Pattern-задания»

  • Индекс: ровно 6 цифр — pattern="[0-9]{6}".
  • Имя пользователя: только латиница и цифры, 3–15 символов — pattern="[A-Za-z0-9]{3,15}".
  • ИНН: ровно 12 цифр.
  • Проверь каждый паттерн в браузере.

Задание 3. «Визуализация»

  • Добавь CSS, чтобы валидные поля имели зелёную рамку, невалидные — красную.
  • Используй :not(:placeholder-shown), чтобы красный не появлялся сразу.

Задание 4. «Сломай и почини»

  • Убери required — увидишь, что форма отправится с пустым полем.
  • Используй pattern="/[0-9]+/" (со слэшами) — увидишь, что не работает.
  • Добавь novalidate к форме — валидация полностью отключится.

Задание 5. «Проверь через DevTools»

  • Открой DevTools (F12) → Elements.
  • Найди поле с required и удали атрибут через правый клик → «Edit as HTML».
  • Отправь форму — увидишь, что браузер больше не проверяет поле.

15. Что запомнить из урока

  • required — поле обязательно.
  • minlength / maxlength — длина текста.
  • min / max — диапазон для чисел и дат.
  • step — шаг изменения числа.
  • pattern — регулярное выражение для формата.
  • type — автоматическая валидация для email, url, number и т.д.
  • placeholder — подсказка, не валидация.
  • CSS: :valid / :invalid — визуализация состояния.
  • novalidate — отключить валидацию формы.
  • Клиентская валидация — для UX, серверная — для безопасности. Обе обязательны.
