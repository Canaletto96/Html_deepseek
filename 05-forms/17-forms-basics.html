Урок 17. Формы — основы

1. Зачем нужны формы

Форма — это способ получить данные от пользователя: логин и пароль, поисковый запрос, комментарий, оформление заказа.

Форма работает так:

  1. Пользователь заполняет поля.
  2. Нажимает кнопку «Отправить».
  3. Браузер собирает данные и отправляет их на сервер.
  4. Сервер обрабатывает и возвращает ответ.

2. Тег <form> — контейнер формы

Все поля формы должны находиться внутри <form>. Это парный тег-обёртка. 

<form action="/submit" method="post">
    <!-- поля формы -->
</form>
Важно: если поля лежат вне <form>, они не отправятся на сервер. Форма — это «коробка», в которую нужно положить все поля.

3. Атрибут action — куда отправить

action — URL, на который браузер отправит данные после нажатия кнопки. Обычно это адрес серверного скрипта. 

<form action="/submit">
<form action="https://example.com/api/login">
<form action="mailto:info@example.com">   <!-- отправить на email -->
Если action пустой или его нет — данные уйдут на текущий URL. Это часто используется в поисковых формах.

4. Атрибут method — как отправить

Два основных метода: GET и POST.

GET POST
Где данные В URL (в строке запроса) В теле запроса (не видно)
Видно в адресной строке Да Нет
Кэшируется Да Нет
Остаётся в истории Да Нет
Ограничение размера ~2000 символов Практически нет
Для чего Поиск, фильтры, ссылки Логин, регистрация, оплата

GET — данные в URL

<form action="/search" method="get">
    <input name="q">
    <button>Найти</button>
</form>

После отправки URL станет таким:

/search?q=html+уроки
Когда использовать GET:
  • Поиск
  • Фильтры и сортировка
  • Ссылка, которую можно сохранить или переслать
  • Запрос, который не меняет данные на сервере

POST — данные в теле запроса

<form action="/login" method="post">
    <input name="login">
    <input name="password" type="password">
    <button>Войти</button>
</form>

После отправки URL останется /login, данные уйдут «скрыто» в теле запроса.

Когда использовать POST:
  • Логин, регистрация
  • Оплата
  • Отправка комментария
  • Загрузка файлов
  • Всё, что меняет данные на сервере
Важно: POST-запросы не защищены сами по себе! Для безопасности нужен HTTPS. Иначе данные (включая пароли) передаются в открытом виде.

6. Атрибут name — имя поля

Критически важный атрибут. Без name поле не отправится на сервер. 

<!-- ПРАВИЛЬНО -->
<input type="text" name="username">

<!-- НЕ ОТПРАВИТСЯ -->
<input type="text">

name — это «ключ», под которым значение уйдёт на сервер. На сервере данные придут как { username: "значение" }.

Правило: у каждого поля формы должен быть name. Исключение — кнопки и декоративные элементы.

7. Атрибуты <form>

Атрибут Значения Описание
action URL Куда отправить данные
method get, post Как отправить
enctype application/x-www-form-urlencoded, multipart/form-data, text/plain Как кодировать данные (важно для файлов)
target _self, _blank и др. Где открыть ответ
autocomplete on, off Автозаполнение браузером
novalidate булев Отключить встроенную валидацию
accept-charset Кодировка: UTF-8 Кодировка при отправке

8. Атрибут enctype — важно для файлов

enctype определяет, как данные кодируются при отправке.

Значение Когда использовать
application/x-www-form-urlencoded (по умолчанию) Обычные текстовые формы
multipart/form-data Обязательно для загрузки файлов (input type="file")
text/plain Редко, для отладки 
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="avatar">
    <button>Загрузить</button>
</form>
Частая ошибка: забыть enctype="multipart/form-data" при загрузке файлов. В этом случае на сервер уйдёт только имя файла, а не сам файл.

9. Атрибут autocomplete

Управляет автозаполнением браузера. Полезно для UX, но иногда его отключают для безопасности (пароли, платёжные данные). 

<form autocomplete="on">   <!-- включить (по умолчанию) -->
<form autocomplete="off">  <!-- отключить -->

Можно задать на уровне формы или отдельного поля:

<form>
    <input name="email" type="email" autocomplete="email">
    <input name="password" type="password" autocomplete="current-password">
    <input name="card" type="text" autocomplete="off">   <!-- отключить -->
</form>
Полезные значения autocomplete:
  • name, email, tel
  • username, current-password, new-password
  • street-address, postal-code, country
  • cc-number, cc-exp, cc-csc — платёжные карты
Браузер подставит сохранённые данные — это огромный плюс для UX.

10. Тег <fieldset> и <legend>

Для группировки связанных полей используют <fieldset> (рамка вокруг группы) и <legend> (заголовок группы). 

<form>
    <fieldset>
        <legend>Личные данные</legend>
        <label>Имя: <input name="firstname"></label>
        <label>Фамилия: <input name="lastname"></label>
    </fieldset>

    <fieldset>
        <legend>Контакты</legend>
        <label>Email: <input type="email" name="email"></label>
        <label>Телефон: <input type="tel" name="phone"></label>
    </fieldset>
</form>
Результат:
Личные данные
Контакты

Зачем: screen reader'ы читают legend при входе в группу — пользователь понимает, что поля относятся к одной категории.

11. Метод GET на практике

Сделаем форму, которая отправляет запрос в Google:

<form action="https://www.google.com/search" method="get" target="_blank">
    <label for="g-q">Найти в Google:</label>
    <input type="text" id="g-q" name="q">
    <button>Искать</button>
</form>

После отправки откроется https://www.google.com/search?q=твой+запрос. Параметр q — это то, что Google ожидает.

Как узнать параметры? Посмотри в URL поиска Google после запроса. Там будет ?q=.... Ты можешь использовать любой сервис так же, если знаешь его параметры.

12. Метод POST на практике

POST не видно в URL, поэтому его надо «поймать» на сервере. Для обучения можно использовать сервис httpbin.org:

<form action="https://httpbin.org/post" method="post" target="_blank">
    <label>Имя: <input name="username"></label>
    <label>Email: <input type="email" name="email"></label>
    <button>Отправить</button>
</form>
Результат (откроется JSON с твоими данными):

Нажми «Отправить» — откроется страница с JSON, где в поле form будут твои данные. Это отличный способ увидеть, что именно уходит на сервер.

14. Полный шаблон формы

<form action="/submit" method="post" autocomplete="on">

    <fieldset>
        <legend>Регистрация</legend>

        <label for="name">Имя:</label>
        <input type="text" id="name" name="name" required>

        <label for="email">Email:</label>
        <input type="email" id="email" name="email" required>

        <label for="password">Пароль:</label>
        <input type="password" id="password" name="password" required>

        <button type="submit">Зарегистрироваться</button>
    </fieldset>

</form>

15. Частые ошибки

Ошибка Почему плохо
Забыть name у поля Поле не отправится на сервер
Использовать GET для паролей Пароль попадёт в URL и историю
Использовать POST для поиска Нельзя сохранить ссылку с результатами
Забыть enctype="multipart/form-data" для файлов Файл не отправится, только имя
Поля вне <form> Не отправятся
Использовать GET для действий, меняющих данные Нарушение HTTP-семантики, можно случайно «повторить» действие
Не указывать action Данные уйдут на текущий URL, что часто не то, что нужно

17. Что запомнить из урока

  • <form> — контейнер формы. Все поля должны быть внутри.
  • action — куда отправить данные (URL сервера).
  • method — как отправить: get (в URL) или post (в теле).
  • GET — для поиска, фильтров. Видно в URL, можно переслать ссылку.
  • POST — для логина, оплаты, файлов. Данные скрыты.
  • name у каждого поля — обязателен.
  • enctype="multipart/form-data" — для загрузки файлов.
  • autocomplete — автозаполнение браузером (ускоряет ввод).
  • <fieldset> + <legend> — группировка полей.
  • Никогда не используй GET для паролей — они попадут в URL.
  • POST не шифрует данные — нужен HTTPS.
  • Браузерная валидация работает автоматически при правильном type.
