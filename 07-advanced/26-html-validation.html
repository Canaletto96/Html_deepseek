Урок 26. Валидация и DevTools

1. Зачем валидировать HTML

Валидация — это проверка кода на соответствие стандарту. Валидный HTML:

  • Работает одинаково во всех браузерах.
  • Лучше для SEO — поисковики понимают структуру.
  • Доступен для screen reader'ов.
  • Легче поддерживать — если сломалось, понятно где.

Браузеры прощают ошибки — «дорисовывают» недостающие теги, закрывают незакрытые. Но это не значит, что ошибки не важны. Браузеры чинят по-разному, и результат может быть непредсказуемым.

2. Типичные ошибки новичков

Ошибка Пример Правильно
Незакрытый тег <p>Текст<p> <p>Текст</p>
Пересечение тегов <strong><em>...</strong></em> <strong><em>...</em></strong>
Атрибут без кавычек <p class=intro> <p class="intro">
Несколько <h1> <h1>A</h1><h1>B</h1> Один <h1> на страницу
Два одинаковых id <p id="a">...<p id="a"> id уникален
Блочный тег внутри строчного <span><div>...</div></span> <div><span>...</span></div>
Забыть alt у картинки <img src="cat.jpg"> <img src="cat.jpg" alt="Кот">
Ссылка без href <a>Текст</a> <a href="...">Текст</a>
Забыть <!DOCTYPE html> Начинается с <html> <!DOCTYPE html> первым
Пустой href="" <a href=""> <a href="#"> или реальный URL

3. W3C Validator — главный инструмент

Официальный валидатор от W3C (организация, которая разрабатывает стандарты веба). Бесплатный, показывает все ошибки с пояснениями.

Сайт: validator.w3.org

Три способа проверить

  1. По URL — вводишь адрес сайта (если уже выложил).
  2. Загрузить файл — выбираешь HTML-файл с компьютера.
  3. Вставить код — копируешь HTML и вставляешь в поле.

Для локальной разработки удобен 3-й способ: скопировал код из VS Code → вставил → проверил.

Что покажет валидатор

  • Errors — реальные ошибки (невалидный HTML).
  • Warnings — предупреждения (не критично, но стоит исправить).
  • Info — просто информация.
Не паникуй от 20 ошибок. Часто одна ошибка (например, незакрытый тег) тянет за собой 5–10 «вторичных». Исправляй сверху вниз — многие исчезнут сами.

5. DevTools — инструменты разработчика

DevTools (Developer Tools) — встроенный в браузер набор инструментов. Открывается клавишей F12 или Ctrl+Shift+I (на Mac: Cmd+Option+I).

Основные вкладки

Вкладка Что там
Elements DOM-дерево, стили, структура страницы
Console Вывод JavaScript, ошибки, можно писать команды
Network Все запросы: HTML, CSS, JS, картинки, API
Sources Исходники файлов, точки останова
Performance Скорость загрузки, узкие места
Application Cookies, LocalStorage, Service Workers
Lighthouse Аудит: SEO, доступность, производительность

6. Elements — самое нужное

Здесь ты видишь как браузер «понял» твой HTML. Если что-то сломалось — здесь это видно.

Что можно делать

  • Разворачивать/сворачивать теги (стрелки слева).
  • Редактировать HTML двойным кликом.
  • Видеть стили справа — какие CSS применились.
  • Искать элементы — Ctrl+F.
  • Копировать — правый клик → Copy → Copy outerHTML.
Важно: изменения в Elements не сохраняются — это только для проверки. При обновлении страницы всё вернётся.

Как проверить структуру

  1. Открой F12 → Elements.
  2. Нажми на стрелку у <body> — увидишь все элементы.
  3. Обрати внимание: браузер сам добавил <head>, <body>, даже если ты их не писал.

7. Console — ошибки и проверки

Console показывает ошибки JavaScript и позволяет писать команды прямо в браузере.

Что искать в Console

  • Красные ошибки — что-то сломалось.
  • Жёлтые предупреждения — не критично, но стоит знать.
  • 404 — файл не найден (неправильный путь).

Проверка через Console

Попробуй ввести в Console (на этой странице):

document.title              // "Урок 26. Валидация и DevTools"
document.querySelectorAll('h2').length   // количество h2 на странице
document.compatMode        // "CSS1Compat" (standards mode)

8. Network — что загружается

Показывает все файлы, которые браузер запрашивает: HTML, CSS, JS, картинки, шрифты, API-запросы.

Как проверить, что все файлы нашлись

  1. Открой F12 → Network.
  2. Обнови страницу (F5).
  3. Смотри столбец Status:
    • 200 — успех ✅
    • 404 — файл не найден ❌
    • 500 — ошибка сервера ❌
Network — главный инструмент для поиска проблем с путями. Если картинка не отображается — открой Network, найди её, посмотри URL. Скорее всего путь неправильный (см. урок 25).

9. Lighthouse — аудит страницы

Встроенный в Chrome инструмент, который проверяет страницу по 4 критериям:

  • Performance — скорость загрузки.
  • Accessibility — доступность (a11y).
  • Best Practices — лучшие практики.
  • SEO — оптимизация для поисковиков.

Открой F12 → Lighthouse → Analyze page load. Через 10–30 секунд получишь отчёт с оценками и рекомендациями.

10. Расширение HTMLHint для VS Code

Если не хочешь каждый раз открывать сайт-валидатор — установи расширение HTMLHint прямо в VS Code.

  1. Открой VS Code → расширения (Ctrl+Shift+X).
  2. Найди «HTMLHint».
  3. Установи.
  4. Теперь ошибки подсвечиваются прямо в редакторе.

Подсветка: жёлтые/красные волны под проблемными местами. Наведи — увидишь описание ошибки.

12. Чек-лист перед публикацией

Перед тем как выложить страницу на сервер, проверь:

  • ☐ Есть <!DOCTYPE html> в первой строке.
  • ☐ Есть <meta charset="UTF-8"> в <head>.
  • ☐ Есть <meta name="viewport">.
  • ☐ Есть <title> (уникальный).
  • ☐ Есть <meta name="description">.
  • ☐ Один <h1> на страницу.
  • ☐ Все <img> имеют alt.
  • ☐ Все id уникальны.
  • ☐ Все теги закрыты.
  • ☐ Нет ошибок в W3C Validator.
  • ☐ В DevTools → Network нет красных 404.
  • ☐ В Console нет красных ошибок.
  • ☐ Lighthouse: хорошие оценки (зелёные).

13. Практическое задание

Задание 1. «Найди ошибки»

Создай файл 26-practice-broken.html с намеренными ошибками:

<html>
<head>
    <title>Тест</title>
</head>
<body>
    <p>Первый параграф
    <p>Второй параграф</p>
    <h1>Заголовок</h1>
    <h1>Ещё заголовок</h1>
    <img src="cat.jpg">
    <div id="x">1</div>
    <div id="x">2</div>
    <strong><em>текст</strong></em>
</body>
</html>
  • Открой validator.w3.org.
  • Вставь код (вкладка «Validate by Direct Input»).
  • Посмотри все ошибки.
  • Исправь сверху вниз и проверь снова.

Задание 2. «DevTools → Elements»

  • Открой этот урок в браузере.
  • Нажми F12 → Elements.
  • Найди <body>, <h1>, <h2>.
  • Посмотри справа стили — какие CSS применились.
  • Поменяй цвет h1 через редактирование стилей (двойной клик по значению).

Задание 3. «DevTools → Console»

  • Открой Console (F12 → Console).
  • Введи: document.title — увидишь заголовок страницы.
  • Введи: document.querySelectorAll('h2').length — количество h2.
  • Введи: document.compatMode — режим документа.

Задание 4. «DevTools → Network»

  • Открой Network, обнови страницу.
  • Найди все файлы — их статус (200/404).
  • Попробуй создать картинку с неправильным путём — увидишь 404.

Задание 5. «Lighthouse»

  • Открой этот урок в Chrome.
  • F12 → Lighthouse → Analyze page load.
  • Посмотри оценки по 4 критериям.
  • Прочитай рекомендации — что можно улучшить.

Задание 6. «HTMLHint в VS Code»

  • Установи расширение HTMLHint в VS Code.
  • Открой файл с ошибками из задания 1.
  • Посмотри, как ошибки подсвечиваются в редакторе.
