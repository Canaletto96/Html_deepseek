Урок 28. Доступность (a11y)

1. Что такое доступность (a11y)

Доступность (accessibility, сокращённо a11y — потому что между a и y 11 букв) — это практика создания сайтов, которые могут использовать все люди, включая:

  • Незрячих — используют screen reader'ы (программы, читающие текст вслух).
  • Слабовидящих — увеличивают шрифт, используют контрастные темы.
  • Глухих — читают субтитры вместо аудио.
  • С моторными нарушениями — не могут пользоваться мышью, только клавиатурой.
  • С когнитивными особенностями — нужен простой язык, понятная структура.

Доступность — это не «для галочки». Это юридическое требование во многих странах (в США — ADA, в Европе — European Accessibility Act). И это просто хорошо для всех.

Интересный факт: доступные сайты лучше для всех. Субтитры помогают в шумном месте. Клавиатурная навигация — быстрее мыши. Высокий контраст — легче читать на солнце.

2. Screen reader — как «видит» незрячий

Screen reader — программа, которая читает содержимое экрана вслух. Популярные:

Программа Платформа Цена
NVDA Windows Бесплатно
JAWS Windows Платно
VoiceOver macOS, iOS Встроен
TalkBack Android Встроен

Screen reader читает не HTML-код, а дерево доступности (accessibility tree) — модель, которую браузер строит из HTML.

Как screen reader «видит» страницу

  • Заголовки — «Заголовок 1: Мой блог».
  • Ссылки — «Ссылка: Главная».
  • Кнопки — «Кнопка: Отправить».
  • Картинки — читает alt.
  • Поля — «Поле ввода: Email».
  • Landmark'и — «Навигация», «Основное содержимое».

Если разметка семантическая — screen reader понимает всё. Если «дивовый суп» — он читает «текст, текст, текст» без структуры.

3. Главное правило доступности

Используй правильные HTML-теги.
80% доступности — это семантическая разметка. <button> вместо <div onclick>. <nav> вместо <div class="nav">. <label> для полей. <alt> для картинок.

ARIA нужен только когда HTML-тегов недостаточно. Это не замена семантике, а дополнение.

4. alt — текст для картинок

Уже проходили в уроке 11, но повторим — это критично для доступности.

Картинка Что в alt
Смысловая (фото, схема) Описание содержания: «Кот спит на подоконнике»
Декоративная (фон, линия) alt="" (пусто — screen reader пропустит)
Картинка-ссылка Куда ведёт: «Перейти на главную»
Кнопка-иконка Действие: «Отправить форму», «Открыть меню»
Логотип «Логотип компании Мурлыка»
Сложный график Кратко + aria-describedby с полным описанием
Плохо:
  • alt="картинка" — не описывает
  • alt="img123.jpg" — имя файла бесполезно
  • Отсутствие alt — screen reader прочитает URL
  • Длинная простыня — alt должен быть кратким

5. Семантические теги и landmark'и

Семантические теги (урок 22) создают landmark'и — «ориентиры», по которым screen reader позволяет прыгать.

Тег Как читает screen reader
<header> «Баннер»
<nav> «Навигация»
<main> «Основное содержимое»
<aside> «Дополнительно»
<footer> «Содержимое подвала»
<section> с заголовком «Регион, [заголовок]»
<form> «Форма»

Пользователь NVDA нажимает D и перескакивает между landmark'ами. Это позволяет пропустить меню и попасть сразу в контент.

6. Клавиатурная навигация

Многие пользователи не могут работать с мышью. Они используют только клавиатуру.

Основные клавиши

Клавиша Что делает
Tab Следующий фокусируемый элемент
Shift+Tab Предыдущий элемент
Enter Активировать кнопку / перейти по ссылке
Space Нажать кнопку, поставить чекбокс
Стрелки Навигация в radio, select
Escape Закрыть dialog, выйти из меню

Что фокусируется автоматически

  • <a href> — ссылки.
  • <button> — кнопки.
  • <input> — поля ввода.
  • <select>, <textarea>.
  • <summary> — заголовки details.

Что НЕ фокусируется

  • <div>, <span> — по умолчанию нет.
  • Ссылки без href.
  • Элементы с disabled.
Проверь сам: нажми Tab на этой странице. Ты увидишь, как фокус переходит между ссылками и кнопками. Обрати внимание на коричневую рамку вокруг активного элемента — это :focus стиль.

Правило видимого фокуса

Никогда не убирай outline без замены! 
/* ПЛОХО */
a:focus { outline: none; }
Пользователь с клавиатурой не увидит, где находится. Если хочешь изменить стиль фокуса — замени его на свой: 
a:focus { outline: 3px solid orange; }

7. ARIA — что это и зачем

ARIA (Accessible Rich Internet Applications) — набор атрибутов, которые добавляют семантику туда, где HTML-тегов не хватает.

Три типа ARIA-атрибутов:

Тип Пример Что делает
Роли (role) role="button" Говорит «это кнопка»
Свойства (aria-*) aria-label="Закрыть" Добавляет описание
Состояния (aria-*) aria-expanded="true" Показывает состояние

8. Главное правило ARIA

«No ARIA is better than bad ARIA»
Лучше без ARIA, чем с плохим ARIA.

Сначала — семантический тег. Если его нет — ARIA. Если не уверен — не используй.

Плохой ARIA

<!-- ПЛОХО: div с role="button" не работает с клавиатуры -->
<div role="button" onclick="submit()">Отправить</div>

Такой «div-кнопка» не фокусируется по Tab, не нажимается Enter/Space. Пользователь с клавиатурой не сможет на неё нажать.

Хорошо — использовать button

<!-- ХОРОШО: настоящая кнопка -->
<button onclick="submit()">Отправить</button>

Работает из коробки: фокус, Enter, Space, доступность для screen reader'ов. ARIA не нужна.

9. Основные ARIA-атрибуты

aria-label — текстовое описание

Для элементов без видимого текста. Например, кнопка-иконка: 

<button aria-label="Открыть меню">
    <svg>...</svg>
</button>
Пример: кнопки-иконки с aria-label:

Screen reader прочитает: «Кнопка: Открыть меню», «Кнопка: Закрыть», «Кнопка: Сохранить».

Правило: aria-label перекрывает видимый текст. Не используй, если есть видимый текст — только для иконок.

aria-labelledby — ссылка на элемент

Когда описание берётся из другого элемента (по id): 

<h2 id="form-title">Регистрация</h2>
<form aria-labelledby="form-title">
    ...
</form>

Screen reader прочитает: «Регистрация — форма».

aria-describedby — подробное описание

Для дополнительной информации (подсказки, формат): 

<label for="phone">Телефон:</label>
<input type="tel" id="phone" aria-describedby="phone-hint">
<p id="phone-hint">Формат: +7XXXXXXXXXX</p>

aria-hidden — скрыть от screen reader

Скрывает от screen reader'а, но оставляет видимым: 

<button>
    <span aria-hidden="true">✓</span>
    Сохранить
</button>

Screen reader прочитает только «Сохранить», а галочка будет только визуальным украшением.

Не используй aria-hidden="true" на фокусируемых элементах! Если что-то доступно с клавиатуры, но скрыто от screen reader'а — это путает пользователя.

aria-expanded — раскрыт ли элемент

Для кнопок, которые раскрывают/скрывают контент: 

<button aria-expanded="false" aria-controls="menu">Меню</button>
<ul id="menu" hidden>...</ul>

Когда меню открыто, JS меняет aria-expanded="true". Screen reader прочитает: «Раскрыто».

aria-live — объявления

Для динамического контента, который нужно объявить screen reader'у: 

<div aria-live="polite">Сообщение об успехе</div>

polite — объявить, когда пользователь закончит текущее действие.
assertive — объявить немедленно (для важного).
off — не объявлять.

10. Формы и доступность

Все поля должны иметь <label>:

<!-- ПРАВИЛЬНО: label связан через for + id -->
<label for="email">Email:</label>
<input type="email" id="email" name="email">

<!-- ПРАВИЛЬНО: обёртка -->
<label>
    Email:
    <input type="email" name="email">
</label>

<!-- ПЛОХО: placeholder вместо label -->
<input type="email" placeholder="Email">
Placeholder — НЕ замена label!
  • Placeholder исчезает при вводе — пользователь забывает, что вводил.
  • Плохо читается (серый, мелкий).
  • Не работает у screen reader'ов как описание поля.
  • Не все screen reader'ы его читают.

Ещё важно для форм:

  • required — обязательные поля.
  • aria-invalid="true" — невалидное поле.
  • aria-describedby — подсказка с форматом.
  • Группировка radio — через <fieldset> + <legend>.

11. Контрастность

Текст должен быть читаемым. Минимум:

Текст Минимальный контраст
Обычный 4.5 : 1
Крупный (от 18pt / 14pt bold) 3 : 1
Кнопки, иконки 3 : 1

Проверить контраст можно:

  • WebAIM Contrast Checker — вводишь два цвета, получаешь результат.
  • DevTools: правый клик на элементе → Inspect → в стилях видишь цвет; наведи — покажет контраст.
  • Lighthouse: в отчёте отдельный раздел про контраст.
Пример контраста (плохой и хороший):

Плохой контраст — почти не видно (3.5% серый на белом).

Хороший контраст — легко читается.

Белый на синем — хороший контраст.

12. Чек-лист базовой доступности

Проверь любую свою страницу:

Семантика

  • ☐ Один <h1> на страницу.
  • ☐ Заголовки в правильной иерархии (h1 → h2 → h3).
  • ☐ Все смысловые блоки — семантические теги (header, nav, main, article, footer).
  • ☐ У каждого <form> есть <label> для полей.
  • ☐ Radio-группы обёрнуты в <fieldset> + <legend>.

Медиа

  • ☐ У всех <img> есть alt.
  • ☐ Декоративные картинки имеют alt="".
  • ☐ У видео есть субтитры (<track>).
  • ☐ У аудио есть транскрипт (текстовая расшифровка).

Клавиатура

  • ☐ Всё работает с клавиатуры (Tab, Enter, Space).
  • ☐ Виден фокус (:focus стиль).
  • ☐ Нет «ловушек фокуса» (когда нельзя выйти из элемента).

Текст

  • ☐ Контраст текста ≥ 4.5:1.
  • ☐ Крупный текст ≥ 3:1.
  • ☐ Шрифт не меньше 16px (для основного текста).
  • ☐ Текст не только цветом (не «красное — ошибка», а «красное + текст «Ошибка»»).

ARIA (только где нужно)

  • ☐ Кнопки-иконки имеют aria-label.
  • ☐ Динамические сообщения — aria-live.
  • ☐ Раскрывающиеся меню — aria-expanded.

13. Практическое задание

Задание 1. «Проверь свою страницу»

  • Возьми любой свой HTML-файл из предыдущих уроков.
  • Пройди по чек-листу из раздела 12.
  • Найди проблемы, исправь.

Задание 2. «Screen reader»

  • Установи NVDA (Windows) или включи VoiceOver (Mac: Cmd+F5).
  • Открой любой свой урок.
  • Попробуй навигировать: по заголовкам (H), по landmark'ам (D), по ссылкам (K).
  • Ты услышишь, как screen reader читает страницу — это очень познавательно.

Задание 3. «Кнопки-иконки»

  • Сделай 3 кнопки с эмодзи: ☰ ✕ 💾.
  • Добавь каждой aria-label с описанием действия.
  • Проверь через screen reader (или через инструменты браузера).

Задание 4. «Клавиатурная навигация»

  • Открой свою страницу.
  • Нажми Tab — пройди по всем ссылкам и кнопкам.
  • Проверь: виден ли фокус (рамка вокруг элемента).
  • Если нет — добавь CSS: :focus { outline: 3px solid #b5651d; }.

Задание 5. «Lighthouse Accessibility»

  • Открой свою страницу в Chrome.
  • F12 → Lighthouse → только Accessibility.
  • Получи оценку. Прочитай рекомендации.
  • Исправь проблемы, проверь снова.

Задание 6. «Контраст»

  • Открой WebAIM Contrast Checker.
  • Введи цвет своего текста и фона.
  • Если контраст < 4.5:1 — замени цвета.
  • Проверь на своей странице.

14. Что запомнить из урока

  • Доступность (a11y) — это не «для галочки». Это нужно всем людям.
  • 80% доступности — это семантическая разметка. Используй правильные теги.
  • alt обязателен для всех картинок. Для декоративных — alt="".
  • Семантические теги создают landmark'и, по которым screen reader позволяет прыгать.
  • Клавиатурная навигация — Tab, Enter, Space, Escape. Всё должно работать без мыши.
  • Видимый фокус — :focus стиль обязателен. Не убирай outline без замены.
  • ARIA — дополнение, а не замена HTML. «No ARIA is better than bad ARIA».
  • aria-label — для кнопок-иконок без видимого текста.
  • aria-labelledby — ссылка на элемент с описанием.
  • aria-describedby — подробное описание (подсказки к полям).
  • aria-hidden="true" — скрыть от screen reader'а, но оставить видимым.
  • aria-expanded — для раскрывающихся элементов (меню, аккордеоны).
  • aria-live — для динамических сообщений.
  • Placeholder — не замена label! Все поля формы должны иметь <label>.
  • Контраст: обычный текст ≥ 4.5:1, крупный ≥ 3:1.
  • Не только цветом: ошибки должны быть видны и текстом, не только красным цветом.
  • Чек-лист из 20+ пунктов — пройди его для каждой страницы.
  • Screen reader — установи NVDA или VoiceOver и послушай свою страницу. Это лучший способ найти проблемы.

16. Полный шаблон доступной страницы

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Моя страница</title>
</head>
<body>

    <!-- Skip link для клавиатурных пользователей -->
    <a href="#main" class="skip-link">Перейти к содержимому</a>

    <header>
        <h1>Название сайта</h1>
        <nav aria-label="Основная навигация">
            <ul>
                <li><a href="/">Главная</a></li>
                <li><a href="/about">О нас</a></li>
            </ul>
        </nav>
    </header>

    <main id="main">

        <article>
            <header>
                <h2>Заголовок статьи</h2>
                <time datetime="2026-01-15">15 января 2026</time>
            </header>

            <img src="photo.jpg" alt="Описание содержания" width="800" height="600">

            <p>Текст статьи...</p>

            <form>
                <label for="email">Email:</label>
                <input type="email" id="email" name="email" required
                       aria-describedby="email-hint">
                <p id="email-hint">Мы не передаём email третьим лицам.</p>

                <button type="submit">Подписаться</button>
            </form>
        </article>

        <aside aria-label="Дополнительная информация">
            <h2>Читайте также</h2>
            <!-- ... -->
        </aside>

    </main>

    <footer>
        <p>&copy; 2026 Мой сайт</p>
    </footer>

</body>
</html>

17. Skip link — «перейти к содержимому»

Один из самых важных приёмов доступности. Пользователь с клавиатуры открывает страницу и первым делом нажимает Tab. У него появляется ссылка «Перейти к содержимому», которая позволяет пропустить меню и сразу попасть в контент. 

<!-- В самом начале body -->
<a href="#main" class="skip-link">Перейти к содержимому</a>

<!-- CSS -->
<style>
.skip-link {
    position: absolute;
    top: -40px;
    left: 0;
    background: #000;
    color: #fff;
    padding: 8px;
    z-index: 100;
}
.skip-link:focus {
    top: 0;
}
</style>

Ссылка скрыта визуально, но появляется при фокусе (когда пользователь нажал Tab). Это экономит кучу времени.

Проверь сам: нажми Tab на этой странице. Первым элементом должна быть ссылка «Перейти к содержимому».

<img> без alt Screen reader читает URL или пропускает
alt="картинка" Бесполезно для незрячих

19. Что запомнить из урока

  • a11y — доступность для всех. Это не «для галочки», а необходимость.
  • 80% доступности — семантика. Правильные теги решают большую часть проблем.
  • alt обязателен для всех картинок. Декоративные — alt="".
  • Все поля формы — с <label>. Placeholder — не замена.
  • Клавиатура: всё должно работать через Tab, Enter, Space.
  • Видимый фокус: никогда не убирай outline без замены.
  • ARIA — только когда HTML не хватает. Не заменяй семантику ARIA.
  • aria-label — для иконок-кнопок. aria-describedby — для подсказок.
  • Контраст ≥ 4.5:1 для обычного текста, ≥ 3:1 для крупного.
  • Skip link — «перейти к содержимому» для клавиатурных пользователей.
  • Инструменты: WAVE, Lighthouse, axe, NVDA, VoiceOver, Contrast Checker.
  • Проверяй с screen reader'ом — это лучший способ найти проблемы.
